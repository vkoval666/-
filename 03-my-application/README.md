# 3. Применение знаний в моём консольном приложении

Задача оценки — не показать, что я знаю команды или определения наизусть, а объяснить, как эти подходы можно использовать в моей разработке.

## Разделение ответственности

Я стараюсь не смешивать в одном месте ввод пользователя, бизнес-логику и работу с внешними ресурсами.

Например, консольный слой получает команду пользователя, отдельный слой выполняет бизнес-операцию, а отдельный компонент может отвечать за сохранение или получение данных.

## Архитектура

При развитии приложения я могу использовать идеи MVP/MVI или Clean Architecture в зависимости от размера и требований проекта. Для небольшого консольного приложения не обязательно строить сложную архитектуру, но полезно сохранять разделение ответственности.

## DI

Если компоненту нужен другой компонент, я предпочитаю передавать его извне. Тогда бизнес-логика не привязывается жёстко к конкретной реализации.

Например, сервис может зависеть от интерфейса хранилища, а конкретное хранилище передаётся при запуске приложения.

## Git

Каждое логическое изменение можно фиксировать отдельным commit. Для отдельной задачи можно создать branch. После проверки изменения отправляются в GitHub.

## Что важно уметь объяснить на оценке

Я должна уметь не только дать определение, но и привести пример из своего приложения: какую ответственность я бы вынесла, какую зависимость передала бы через DI, где находится интерфейс пользователя и почему изменение одного компонента не должно ломать остальные.
