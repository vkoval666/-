# Git workflow для оценки

В репозитории есть основная ветка `main`. Для отдельной задачи используется отдельная branch.

Типичный workflow:

1. создать branch от актуального `main`;
2. сделать логические commits;
3. отправить branch в GitHub;
4. открыть Pull Request;
5. проверить изменения и получить review;
6. после проверки merge в `main`.

Если опубликованное изменение нужно отменить, безопасный вариант — `revert`, потому что он сохраняет историю.

## Как это применимо ко мне

Я могу объяснить не только определения Git-команд, но и процесс разработки: задача → branch → commits → Pull Request → review → merge → при необходимости revert.
