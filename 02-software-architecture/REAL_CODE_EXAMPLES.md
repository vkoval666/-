# Архитектура: примеры из реального кода

## 1. Composition Root

`complexos/complexos.ts` собирает приложение: создаёт и подключает ERP, devices, queue manager, order processor, media manager, config manager, API и watchdogs.

Это можно использовать как пример места, где приложение получает зависимости и связывает компоненты.

## 2. Dependency Injection

`createOrderProcessor({...})` получает готовые зависимости (`bus`, `devices`, `erp`, `redis`, менеджеры и очередь), вместо того чтобы создавать их внутри обработчика заказов.

То же видно в других фабриках: `createDeviceManager({ bus, devices, world })`, `createMediaManager({ redis, baseDir })`, `makeQueueManager({ bus, devices, operatingModeManager, world })`.

## 3. Абстракции устройств

В `cm-drv` есть несколько реализаций кофемашин и фабрики (`eversys`, `wmf`, `drinkx`, `fake`). Это позволяет отделять общую логику драйвера от конкретного оборудования.

## 4. Resources

ComplexOS загружает конфигурацию, продукты, supply data, media, avatars и backgrounds. Эти данные являются ресурсами, которыми пользуется логика приложения.

## 5. MVP

Если строить консольный интерфейс в MVP:

- View — REPL/консоль;
- Presenter — обработчик пользовательской команды;
- Model — состояние и бизнес-операции ComplexOS.

## 6. MVI

В MVI команда пользователя может рассматриваться как Intent. Обработчик превращает Intent в новое состояние, а View отображает это состояние. Для сложного UI такой однонаправленный поток делает изменения состояния предсказуемыми.

## 7. Clean Architecture

Не следует говорить, что проект полностью реализует каноническую Clean Architecture. Правильнее: в проекте применяются её полезные принципы — разделение ответственности, выделение инфраструктуры и передача зависимостей через границы компонентов.

## Формулировка для оценки

«Я посмотрела на архитектуру не как на набор папок, а как на зависимости. Точка входа собирает приложение, бизнес-компоненты получают зависимости извне, работа с устройствами выделена отдельно, а ресурсы и инфраструктура не смешиваются с каждой бизнес-операцией».
