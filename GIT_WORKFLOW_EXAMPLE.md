# Практический Git workflow в этом репозитории

Этот репозиторий создан для демонстрации полного жизненного цикла изменения:

`main → feature branch → commits → Pull Request → review → merge`

После merge история остаётся в Git, а если изменение окажется ошибочным, его можно отменить через `revert`, не переписывая опубликованную историю.

Для оценки важно уметь объяснить назначение каждого этапа, а не просто знать название команды.
