# 7. Вопросы для устной оценки

## Git

**Что такое Git?**

Распределённая система контроля версий, которая хранит историю изменений проекта.

**Что такое commit?**

Зафиксированное логическое изменение в истории проекта.

**Зачем branch?**

Чтобы вести отдельную линию разработки и не смешивать незавершённую задачу с основной веткой.

**Что делает revert?**

Создаёт новое изменение, отменяющее предыдущий commit, сохраняя историю.

**Что такое fork?**

Независимая копия репозитория в другом аккаунте или пространстве GitHub.

**Public и Private?**

Public виден всем, Private доступен только владельцу и разрешённым пользователям.

## Архитектура

**Зачем нужна архитектура?**

Чтобы разделить ответственность компонентов, уменьшить связанность и сделать систему удобнее для изменения и тестирования.

**MVP и MVI?**

Обе модели разделяют UI и внутреннюю логику. В MVP центральную роль играет Presenter, в MVI — однонаправленный поток Intent → изменение состояния → View.

**Что такое Clean Architecture?**

Подход к организации системы, при котором бизнес-правила отделены от деталей инфраструктуры и зависимости направлены к внутренним слоям.

**Зачем выносить Resources?**

Чтобы отделить данные и ресурсы от программной логики и упростить их изменение.

**Что такое DI?**

Передача зависимостей компоненту извне вместо самостоятельного создания конкретных зависимостей.

## Linux и логи

**Как искать проблему в Linux?**

Сначала определить компонент, затем проверить его состояние, процессы, конфигурацию и логи, а при необходимости — сетевые зависимости.

**Как читать лог?**

Смотреть не отдельную ошибку, а последовательность событий до и после неё и сравнивать её с успешным сценарием.
