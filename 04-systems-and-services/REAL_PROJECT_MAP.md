# Карта реального ПО

## Состав релиза

По структуре `erp-release-6009` видны следующие крупные части:

- `complexos` — ComplexOS, центральная логика sales point;
- `complexui` — пользовательский интерфейс;
- `front-erp` — ERP frontend;
- `mobile-api` — API мобильного приложения;
- `cm-drv` — драйвер кофемашины;
- `svc` — серверные сервисы;
- `megadb` — слой работы с данными;
- `gw` — gateway;
- `supervisor` — управление/координация компонентов;
- `watchdog` — контроль состояния;
- `lib` — общие библиотеки;
- `scripts` — вспомогательные скрипты.

## Взаимодействие на верхнем уровне

Упрощённо поток можно представить так:

`UI / API → ERP / gateway → ComplexOS → service transport / bus → драйверы и hardware`

При этом отдельные сервисы могут иметь собственные зависимости и интерфейсы.

## ComplexOS

В точке входа ComplexOS поднимаются конфигурация, ERP, устройства, обработчик заказов, очереди, API, медиаменеджер, диагностика, логирование и watchdogs.

Это хороший пример системы, где точка входа только собирает приложение, а ответственность распределена между модулями.

## Coffee Machine Driver

`cm-drv` отвечает за взаимодействие с кофемашинами и железом. В коде предусмотрены разные реализации/фабрики, включая Eversys, WMF, DrinkX и fake.

Это пример абстракции: основной код может работать через общий интерфейс, а конкретная реализация выбирается конфигурацией.

## Что отвечать на оценке

Если меня спрашивают «что у вас за система?», я не называю только один файл. Я объясняю, что это комплекс из нескольких приложений и сервисов, где ComplexOS координирует работу sales point, UI/API обеспечивают взаимодействие с пользователем и внешними системами, а драйверы связывают программную часть с оборудованием.
