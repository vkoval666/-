# 1. Git и GitHub

## Система контроля версий

Система контроля версий хранит историю изменений проекта. Она позволяет видеть, что менялось, кто и когда это изменил, возвращаться к предыдущему состоянию и безопасно работать нескольким разработчикам.

**Git** — распределённая система контроля версий. **GitHub** — платформа для хранения Git-репозиториев и совместной работы.

## Repository

Репозиторий — проект вместе с его историей изменений.

В моей разработке репозиторий нужен, чтобы хранить исходный код и историю его развития.

## Commit

Commit — зафиксированное логическое изменение в истории проекта.

Хороший commit описывает законченное изменение: например, исправление ошибки или добавление отдельной функции.

## Revert commit

Revert создаёт новое изменение, которое отменяет эффект предыдущего commit. История при этом сохраняется.

Я бы использовала revert, если уже опубликованное изменение оказалось ошибочным и нужно безопасно вернуть рабочее поведение.

## Push

Push отправляет локальные commits в удалённый репозиторий.

## Pull

Pull получает изменения из удалённого репозитория и интегрирует их в локальную ветку.

## Branch

Ветка — отдельная линия разработки. Она позволяет работать над задачей, не ломая основную ветку.

В своей разработке я бы создавала отдельную ветку под новую задачу или исправление, проверяла изменения и затем объединяла их с основной веткой.

## Fork

Fork — независимая копия чужого репозитория в своём GitHub-аккаунте. Часто используется для работы с проектами, куда нет прямого права записи.

## Public / Private

Public-репозиторий виден другим пользователям. Private доступен только владельцу и разрешённым участникам.

Для рабочего кода выбор зависит от политики компании и конфиденциальности проекта.

## Как применяю

Я использую Git как историю разработки: каждое значимое изменение фиксирую commit, для отдельной задачи могу использовать branch, готовые изменения отправляю push, а при необходимости отменить уже опубликованное изменение использую revert. GitHub используется как удалённое хранилище и место совместной работы.
